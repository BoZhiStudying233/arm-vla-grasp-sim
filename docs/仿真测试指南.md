# pct_scene 仿真测试指南

本文说明如何在评测机启动 Isaac Sim，在独立 GPU 服务器运行 StarVLA，并通过 SSH 本地端口转发完成远程评测。模型服务只监听服务器 `127.0.0.1`；pct_scene 也只接受回环 `ws://` endpoint。

## 1. 测评架构

```text
GPU 服务器
  StarVLA checkpoint
  -> route + subtask
  -> NAV: body-frame [dx,dy,dyaw] chunk
  -> GRASP/PLACE: base-frame [x,y,z,roll,pitch,yaw,gripper] chunk
       |
       | SSH -L，仅回环端口
       v
评测机 pct_scene
  front/wrist + base/arm state encoder
  -> 协议、request ID、超时和安全校验
  -> NAV waypoint 转世界系 -> DWA -> locomotion policy
  -> GRASP/PLACE route/TCP shadow -> 本地 cuRobo 确定性抓放
  -> Isaac 状态机、物理验证、events.jsonl、summary.json
```

`run_full_physics_pipeline.py` 原本用于数采，但它拥有唯一的 Isaac 生命周期、导航、cuRobo、状态机和 recorder。`--remote-vla-eval` 只替换远程策略与 NAV 规划层，不复制第二套仿真运行时；因此它也是模型测评入口。

## 2. 当前两种模式

### `route_only`

- 模型控制 route/subtask 和 NAV waypoint。
- GRASP/PLACE 只要求 route 正确，机械臂仍执行本地确定性 cuRobo。
- 可评价 route、subtask、NAV 和“混合基线”完整任务成功率。
- 完整任务成功不能作为机械臂 action head 指标。

### `shadow`

- 在 `route_only` 基础上，GRASP/PLACE 必须返回 `arm_targets_base`。
- 每个 TCP target 检查 base-frame workspace、相邻位移、相邻转角和夹爪范围。
- 模型 TCP 只写入事件和 summary，不生成关节命令；物理抓放仍由 cuRobo 完成。
- 可用于真实 action checkpoint 上线前的在线分布和安全拒绝率评测。

当前没有把模型 TCP chunk 直接执行为 cuRobo/关节轨迹。训练动作是滚动短视野目标，不能粗暴取首尾点拼成一次完整抓放。只有完成滚动机械臂 planner/executor、碰撞检查和 Isaac smoke 后，才能新增物理 `model` 模式。

当前 NAV-only checkpoint 应使用 `route_only`；尚未训练好的 GRASP/PLACE action head 在 `shadow` 下失败属于预期。

## 4. 启动模型服务

每次先由用户确认使用 `zju-server` 还是 `robotdiff_new`，再检查 GPU 进程归属。不要停止或复用他人的进程。所有服务使用独立 tmux：

```bash
cd /path/to/starVLA_sc
CHECKPOINT=/absolute/path/to/final_model/pytorch_model.pt \
GPU=<空闲卡> PORT=10093 TMUX_SESSION=go2_vla_sim_eval \
scripts/evaluation/start_go2_vla_server_tmux.sh
```

检查：

```bash
tmux capture-pane -pt go2_vla_sim_eval:server -S -120
ss -lntp | grep 10093
```

监听地址必须是 `127.0.0.1:10093`。checkpoint metadata、动作维数和数据归一化配置必须与本次模型一致。

## 5. 建立评测机隧道

在运行 pct_scene 的评测机执行：

```bash
cd /home/natural/Desktop/mtr/pct_scene
LOCAL_PORT=10093 REMOTE_PORT=10093 \
  scripts/evaluation/manage_remote_vla_tunnel.sh start zju-server
LOCAL_PORT=10093 REMOTE_PORT=10093 \
  scripts/evaluation/manage_remote_vla_tunnel.sh check zju-server
```

若服务器是 `robotdiff_new`，替换 SSH alias。不要把 `--vla-endpoint` 写成服务器公网 IP。

## 6. 单 episode route-only 基线

```bash
cd /home/natural/Desktop/mtr/pct_scene
export ISAAC_PYTHON=/home/natural/miniconda3/envs/isaac_locomani/bin/python
export PCT_SCENE_OUTPUT="${PCT_SCENE_OUTPUT:-$HOME/pct_scene_outputs}"

PYTHONDONTWRITEBYTECODE=1 "$ISAAC_PYTHON" -B \
  scripts/pipeline/run_full_physics_pipeline.py \
  --scene-profile liangzhu \
  --output-dir "$PCT_SCENE_OUTPUT/liangzhu_vla_route_only_seed3000" \
  --seed 3000 \
  --remote-vla-eval \
  --vla-endpoint ws://127.0.0.1:10093 \
  --vla-arm-mode route_only \
  --vla-connect-timeout-s 10 \
  --vla-response-timeout-s 120 \
  --vla-max-replans 64 \
  --vla-max-chunk-steps 250 \
  --no-record-dataset \
  --no-record-video \
  --headless
```

默认不采 overview、不制作视频。需要人工复核时使用 `--no-headless --keep-window-open --overview`；只有显式 `--overview` 才采 overview 并制作视频。

## 7. 单 episode arm shadow

确认 checkpoint 已训练 10 维 GRASP/PLACE action 后运行：

```bash
PYTHONDONTWRITEBYTECODE=1 "$ISAAC_PYTHON" -B \
  scripts/pipeline/run_full_physics_pipeline.py \
  --scene-profile liangzhu \
  --output-dir "$PCT_SCENE_OUTPUT/liangzhu_vla_arm_shadow_seed3000" \
  --seed 3000 \
  --remote-vla-eval \
  --vla-endpoint ws://127.0.0.1:10093 \
  --vla-arm-mode shadow \
  --vla-response-timeout-s 120 \
  --vla-max-replans 64 \
  --vla-max-chunk-steps 250 \
  --no-record-dataset \
  --no-record-video \
  --headless
```

shadow 验收重点是 `remote_vla_route_decision` 事件中的 `arm_shadow_report`、target 数量、位移/转角步长、拒绝原因和推理延迟。物理抓放结果仍标记为确定性 cuRobo 结果。

## 8. 批量评测

单 episode 通过后再扩大 batch：

```bash
PYTHONDONTWRITEBYTECODE=1 "$ISAAC_PYTHON" -B \
  scripts/pipeline/run_full_physics_batch.py \
  --scene-profile liangzhu \
  --output-dir "$PCT_SCENE_OUTPUT/liangzhu_vla_route_only_n20" \
  --num-episodes 20 \
  --seed 3000 \
  --remote-vla-eval \
  --vla-endpoint ws://127.0.0.1:10093 \
  --vla-arm-mode route_only \
  --vla-response-timeout-s 120 \
  --vla-max-replans 64 \
  --vla-max-chunk-steps 250 \
  --no-record-dataset \
  --no-record-video \
  --headless \
  --continue-on-failure
```

`batch_summary.jsonl` 每条记录包含 episode 成败、失败阶段和 `remote_vla` 遥测。不要把在线仿真无 GT 的 subtask 输出计算成 exact accuracy；route/subtask exact 仍在 StarVLA held-out evaluator 中统计。

## 9. 结果检查

每个 episode 至少检查：

- `events.jsonl`：route/subtask、模型目标、状态迁移和失败原因。
- `summary.json`：`remote_vla.inference_count`、route/phase counts、平均/最大 roundtrip、最后决策和 arm shadow 报告。
- `frames.jsonl`/`data.csv`：执行动作和后验状态；关闭 dataset 时仍保留评测 recorder 的结构化证据。
- `current_state_curobo/`：当前确定性抓放的规划输入、轨迹和结果。

报告指标应分开：route/subtask、NAV 到达率、NAV 重规划/过期/超时率、arm shadow 合法率、确定性 cuRobo 规划成功率、抓取/放置/完整任务成功率。禁止用混合基线完整成功率代替 action-head 物理指标。

## 10. 安全退出与故障

停止新 episode，退出评测进程后关闭本任务隧道和模型 tmux；不要终止其他用户进程：

```bash
LOCAL_PORT=10093 REMOTE_PORT=10093 \
  scripts/evaluation/manage_remote_vla_tunnel.sh stop zju-server
```

- `protocol version mismatch`：同步 starVLA_sc 与 pct_scene。
- `request_id mismatch`：响应过期或串线，立即拒绝。
- `remote_vla_waypoint_chunk_expired`：当前 chunk 执行过久，安全停车并终止 episode。
- `NAV response has no nav_waypoints`：route/action 合同不一致。
- `grasp/place decision has no arm_targets_base`：`shadow` 模式下 checkpoint 不具备完整机械臂输出。
- arm workspace/step 超限：记录模型失败，不调宽门限掩盖问题。
- 网络中断：当前 tick 返回 idle，episode 标记失败，禁止复用旧 waypoint。
